## 입력에서 출력까지
| 구분 | 설계 |
|---|---|
| 입력 데이터 | 사진, 기록 제목/설명, 아이템별 상품명/옵션 |
| Trigger | 상품명/옵션 입력이 잠시 멈춤 |
| 처리/변환 | 공백 정리 → 중복 입력 검사 → Python API → Codyssey 후보 정규화 |
| 조건 분기 | 빈 입력이면 호출하지 않음. 입력 변경 시 이전 확인 해제. 오래된 응답 무시. 오류 시 입력 유지·명시적 재시도 |
| Action/출력 | “이 제품 맞아요?” → 사용자 확인 → 후보와 searchQuery를 기록에 저장 |
| 실행 로그와 오류 확인 | 브라우저 네트워크 호출 수, 서버 상태코드, 저장 결과를 검증. 키와 입력 원문을 서버 로그에 남기지 않음 |

Detail 흐름: 기록 ID → localStorage 조회 → 사진/아이템 표시 → encodeURIComponent(searchQuery)로 네이버 쇼핑 링크 생성. AI 요청 없음.

## 필수 검증
| 시나리오 | 통과 기준 |
|---|---|
| 빠른 연속 입력 | 입력이 멈춘 뒤 최종 입력으로 1회 요청 |
| 같은 값 재입력 | 동일 입력으로 자동 중복 요청하지 않음 |
| 응답 대기 중 입력 변경 | 이전 응답이 새 후보를 덮어쓰지 않음 |
| 후보 확인 후 입력 변경 | 기존 확인 및 searchQuery를 그대로 저장하지 않음 |
| 저장 후 새로고침 | 사진과 아이템 목록 유지 |
| Detail 진입·검색 클릭 | AI 호출 0회, 저장한 검색어가 링크에 반영됨 |
| API 시간 초과·실패 | 입력 보존, 오류 안내, 무한 재시도 없음 |
| 저장 용량 초과 | 실패 표시, 성공 이동 없음, 이전 기록 유지 |
| 잘못된 기록 ID | 찾을 수 없음과 Feed 링크 표시 |
| 모바일 360px·키보드 | 가로 넘침 없음, 주요 조작 사용 가능 |

## 학습과 기록
사용자가 설명할 핵심: 입력 → 조건 판단 → AI 후보 → 확인 → 저장 → 검색 링크.
AI가 처리할 반복 부분: 공통 헤더 연결, 저장 유틸리티, 오류 표시, 테스트 준비.
README에는 문제·설계 이유·실행 방법·검증 결과·제한·개선점을 남긴다.
지금 반드시 이해: AI는 Upload에서 후보를 제안하고, Detail은 저장된 검색어만 사용한다.
