# A1-2 Pre-submission Checklist

제출 전에는 이 문서를 기준으로 실제 파일과 README 내용을 대조한다.

## 1. 원문 요구사항 확인

- [x] 미션 원문을 다시 읽었다.
- [x] 필수 산출물을 모두 표시했다.
- [x] 선택/보너스 과제를 필수와 분리했다.
- [x] 제출 방식, 파일명, 폴더명 조건을 확인했다.
- [x] 금지 조건이나 제한 조건을 확인했다.

## 2. 기능 요구사항 확인

- [x] 필수 기능이 모두 구현됐다.
- [x] 입력 예외 상황을 처리한다.
- [x] 출력 형식이 미션 요구와 맞다.
- [x] 데이터 저장 또는 파일 생성 요구가 있으면 실제로 동작한다.
- [x] 보너스 기능은 실제 구현한 것만 문서에 적었다.
- [x] 결과 캐싱과 복수 지역 추천은 선택 보너스로, `--multi-region` 선택 모드와 함께 구분했다.
- [x] raw JSON만 남은 같은 날짜를 재실행해 API 호출 없이 Markdown이 재생성되는지 확인했다.
- [x] LLM Markdown에 필수 섹션이 없을 때 fallback 리포트로 대체되는지 확인했다.
- [x] 복수 지역의 0건·API 오류가 다른 지역 처리를 중단하지 않는지 확인했다.
- [x] 단일/복수 캐시 형식이 서로 재사용되지 않는지 확인했다.

## 3. 문서 확인

- [x] README에 미션명과 목적이 적혀 있다.
- [x] README의 실행 방법과 `--multi-region` 선택 실행 방법이 적혀 있다.
- [x] 주요 기능 목록이 실제 구현과 일치한다.
- [x] 요구사항 대응표가 있다.
- [x] 미션 원문에 별도 스크린샷 요구가 없음을 확인했다.
- [x] 참고 링크를 임의로 추가하지 않았다.

## 4. AI 결과 검토

- [x] 원문에 없는 조건을 만들어내지 않았다.
- [x] 필수 산출물을 빠뜨리지 않았다.
- [x] 기능 요구사항을 잘못 해석하지 않았다.
- [x] 복수 지역은 선택 옵션으로 분리해 필수 조건으로 만들지 않았다.
- [x] 어려운 개념은 쉬운 말로 풀어 썼다.
- [x] 참고자료 링크를 지어내지 않았다.

## 5. 실행 및 검증

- [x] 프로그램 실행을 확인했다.
- [x] 문법 검사를 했다.
- [x] 필요한 테스트를 실행했다(19개 통과).
- [x] 생성 파일이 올바른 위치에 만들어지는지 확인했다.
- [x] 오류 메시지가 사용자에게 이해 가능하게 나온다.

## 6. Git 확인

- [x] `git status`로 변경 파일과 제외 파일을 확인했다.
- [x] 루트의 unrelated PNG는 커밋 대상에서 제외했다.
- [ ] 제출 대상 파일이 모두 추적 대상에 포함됐다.
- [ ] 필요한 경우 커밋 메시지를 기능 단위로 작성했다.

## 7. 최종 제출 판단

- [ ] 원문 기준으로 필수 조건을 모두 만족한다.
- [ ] 실행 방법과 실제 실행 결과가 일치한다.
- [ ] 과장된 설명 없이 구현한 내용만 설명한다.
- [ ] 제출자가 직접 이해하고 설명할 수 있는 상태다.
