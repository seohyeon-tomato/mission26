# A1-2 작업 분석

## 목표와 범위

날짜 한 개를 받아 여행지를 추천하고, 장소 검색 결과를 붙여 여행 계획 파일로 저장하는 것이 핵심입니다. 이 구현은 OpenAI 계열 API와 Kakao Local을 연결했습니다. 기본 흐름을 먼저 완성한 뒤, 반복 실행 비용을 줄이는 캐시와 여러 도시를 다루는 선택 모드를 더했습니다.

## 결과물과 완료 기준

| 산출물 | 확인 기준 | 현재 상태 |
| --- | --- | --- |
| CLI 프로그램 | 날짜 옵션을 받고 형식을 검사한다 | 구현 및 실행 확인 |
| 원본 JSON | 추천·검색 결과·오류를 한 파일에 담는다 | 날짜별 파일 생성 확인 |
| 여행 보고서 | 추천 설명과 하루 일정이 Markdown으로 저장된다 | 실제 생성 확인 |
| 사용 안내 | 키 설정, 실행, 출력 위치를 설명한다 | README 작성 |

## 데이터가 흐르는 방식

```text
날짜 옵션
  → 날짜 검사와 키 로딩
  → LLM의 추천 JSON
  → JSON 검증 및 필요 시 1회 재요청
  → 추천 도시로 Kakao 맛집 검색
  → 추천·검색 결과를 바탕으로 Markdown 생성
  → JSON과 Markdown 파일 저장
```

입력 단계에서 날짜가 잘못되었거나 필수 키가 없으면 API 단계로 넘어가지 않습니다. 장소 검색이 실패하거나 결과가 비어도 `errors`에 기록하고 보고서 생성을 계속합니다. 최종 보고서 형식이 빠진 경우에는 기본 템플릿을 사용합니다.

## 요구사항 점검표

| 항목 | 구현 위치 또는 확인 방법 | 상태 |
| --- | --- | --- |
| CLI와 날짜 형식 검사 | `parse_args()` / `--help` 및 입력 검사 | 확인 |
| 추천 JSON 스키마 | `generate_recommendation()` 및 검증 함수 | 확인 |
| JSON 파싱 실패 재시도 | 잘못된 응답을 한 차례 재요청하는 테스트 | 확인 |
| Kakao 맛집 검색 | `KakaoPlaceSearchProvider` | 실제 호출 확인 |
| 검색 0건·오류 대응 | 빈 결과와 예외를 `errors`에 남김 | 테스트 확인 |
| Markdown 결과 | `generate_report()` 및 fallback 함수 | 실제 파일 확인 |
| 결과 캐시 | 날짜와 실행 모드가 맞는 raw JSON 검사 | 회귀 테스트 확인 |
| 여러 도시 처리 | `--multi-region` 및 도시별 검색 루프 | 회귀 테스트 확인 |
| 키 보호 | `.env`, 환경변수, `.gitignore` | 저장소에서 `.env` 제외 확인 |

## 선택 기능

`--multi-region`은 두세 도시를 추천해 각 도시의 음식점을 따로 찾습니다. 캐시는 날짜뿐 아니라 단일/복수 모드도 함께 비교합니다. 따라서 서로 다른 형식의 결과 파일을 섞어 쓰지 않습니다. 기존 raw JSON만 있고 Markdown이 비어 있거나 빠졌으면 외부 API를 부르지 않고 보고서를 다시 만들 수 있습니다.
