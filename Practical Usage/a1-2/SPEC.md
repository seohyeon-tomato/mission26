# 여행 추천 CLI 설계 메모

## 사용자 관점

사용자는 터미널에서 여행 날짜를 입력하고 실행합니다. 프로그램은 도시 추천과 음식점 정보를 모아 Markdown 계획을 저장하고, 화면에는 진행 단계와 저장 경로를 보여줍니다.

## 인터페이스

```bash
python3 travel_planner.py --date "YYYY-MM-DD"
python3 travel_planner.py --date "YYYY-MM-DD" --multi-region
```

`--date`는 필수이며 `-date` 별칭도 지원합니다. 날짜가 올바르지 않으면 사용법과 오류를 표시하고 종료합니다.

## 구성과 책임

| 부분 | 책임 |
| --- | --- |
| CLI | 인자 파싱, 날짜 형식 확인 |
| 설정 | `.env`와 환경변수에서 API 키·모델 읽기 |
| 추천 단계 | OpenAI 요청, JSON 파싱, 구조 검증, 파싱 오류 1회 재시도 |
| 장소 단계 | Kakao 키워드 검색, 검색 오류 분류 |
| 보고서 단계 | Markdown 생성, 필수 제목 확인, 기본 보고서 대체 |
| 저장 단계 | 날짜별 원본 JSON과 Markdown 기록, 저장 실패 기록 |

## 주요 데이터

단일 추천의 최소 구조:

```json
{
  "recommended_city": "도시명",
  "weather": "계절에 대한 설명",
  "events": ["행사 후보"],
  "reason": "추천 이유 두 문장 이상"
}
```

복수 추천에서는 `recommended_cities`와 도시별 `region_details`를 사용합니다. 저장 파일에는 여행 날짜, 추천 내용, 맛집 목록, `errors`를 담습니다. 복수 모드에서는 맛집이 `restaurants_by_city` 아래 도시별로 나뉩니다.

## 오류와 복구

- 날짜 오류 또는 키 누락: API 요청 없이 실행을 끝내고 입력 수정 방법을 안내합니다.
- 추천 JSON의 파싱·검증 실패: 한 번 다시 요청하고, 재실패하면 오류로 종료합니다.
- Kakao 검색의 0건·실패: 결과를 빈 목록으로 두고 오류를 기록한 뒤 다음 단계로 진행합니다.
- 최종 보고서 생성 실패 또는 필수 섹션 누락: 로컬 기본 보고서를 사용합니다.
- 파일 쓰기 실패: 가능한 오류 내용을 결과의 오류 목록과 터미널에 알립니다.

## 캐시 규칙

여행 날짜와 모드가 일치하고 필수 데이터가 있는 raw JSON만 재사용합니다. 단일 추천 캐시와 복수 추천 캐시는 서로 대체하지 않습니다. 보고서 파일이 없거나 내용이 불완전하면 API 대신 저장된 raw JSON으로 다시 구성합니다.

## 보안·제약

- 실제 키는 `.env` 또는 환경변수로만 전달하고 Git에 올리지 않습니다.
- 네트워크 응답에 포함된 정보는 서비스 권한과 시점에 따라 달라질 수 있습니다.
- 날씨·행사 설명은 추천용 요약이며 공식 일정 확인을 대체하지 않습니다.
- 별도 패키지 설치 없이 Python 표준 라이브러리만 사용합니다.
