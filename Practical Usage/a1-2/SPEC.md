# A1-2 Mission Workspace Spec

## 목표

사용자가 A1-2 미션 원문을 보내면, 원문을 기준으로 미션 핵심 요약, 필수/선택 산출물, 진행 순서, 요구사항 체크, 제출 구조, AI 결과 검토, 제출 전 점검까지 일관되게 정리하고 실제 산출물 제작으로 이어지게 한다.

## 입력 자료

- 사용자가 붙여 넣는 A1-2 미션 원문
- 이후 사용자가 제공하는 추가 조건, 예시, 스크린샷, 실행 결과
- 저장소 안에 생성되는 코드, 문서, 검증 자료

## 작업 단계

1. 미션 원문을 `mission_brief_template.md` 기준으로 분석한다.
2. 원문에 명시된 필수 산출물과 선택/보너스 과제를 분리한다.
3. 모호한 조건은 단정하지 않고 확인 질문으로 남긴다.
4. 기능 요구사항을 체크리스트로 바꾸고 구현 우선순위를 정한다.
5. 제출물 폴더 구조와 파일명을 먼저 설계한다.
6. 산출물을 만든 뒤 AI 결과 검토 규칙에 따라 오류, 과장, 누락을 점검한다.
7. 제출 전 체크리스트로 실행, 문서, Git 상태를 확인한다.

## 산출물

- `README.md`: A1-2 작업공간 사용 안내
- `mission_brief_template.md`: 미션 원문 분석 및 산출물 설계 템플릿
- `pre_submission_checklist.md`: 제출 전 점검 체크리스트
- `handoff.md`: 현재 진행 상황과 다음 작업 기록

## 검증 방법

- 미션 원문에 없는 요구사항을 추가하지 않았는지 확인한다.
- 필수 산출물이 모두 체크리스트에 들어갔는지 확인한다.
- 선택/보너스 과제를 필수처럼 표현하지 않았는지 확인한다.
- 모호한 조건은 확인 질문으로 남겼는지 확인한다.
- 최종 제출 구조가 실제 파일 구조와 일치하는지 확인한다.

## 확인 질문

- A1-2 미션 원문 전체를 보내주면 이 템플릿에 맞춰 첫 분석본을 작성한다.
- 미션에서 요구하는 언어, 실행 환경, 제출 방식이 있으면 원문 그대로 우선한다.
